## 1. 项目定位

IceGuard 是一个**纯本地**的 Android 安全守护应用。它不做"云查杀"、不收集样本、
不申请网络权限，而是在设备端用**可解释的启发式规则**完成三类分析：

1. **应用权限审计**——枚举已安装应用，按权限组合与组件暴露面评估风险。
2. **安装包静态扫描**——解析本地 APK 的二进制清单（权限 + 组件 + 安装来源），评估风险。
3. **设备环境检测**——探测 Root 痕迹、危险设置、无障碍服务、设备管理器等。

在此之上提供：**一键体检评分**、**报告导出（Markdown / JSON）**、
**安全守护**（四条检测通道 + 事件驱动的秒级响应），以及可选的
**应用处置**（需用户显式授权 Shizuku）。

### 明确不做的事

以下能力在非 Root 的现代 Android 上第三方应用**无法实现**，因此本项目不提供：

- 实时**行为**监控与"监控到病毒发作再击杀"——系统隔离了应用间观测。
  本项目的替代方案是**事件驱动的秒级响应**：终止真实生效（亚秒级 `am force-stop`），
  但触发时机是**可观测事件**（安装 / 开机 / 前台唤醒 / 周期巡检），不是"发作瞬间"。
- 云端病毒库比对（本项目不联网，也不收集样本）
- 用无障碍服务模拟点击"清理"
- 安装前阻止安装（系统没有给第三方应用这个 API）

## 3. 分层架构

项目采用**四层**结构，依赖方向自上而下，`core` 层不依赖 `ui` 层：

```
┌──────────────────────────────────────────────────────────────┐
│  ui 层（视图 · 仅依赖 core / data / di）                        │
│  MainActivity  AuditActivity  ApkScanActivity                  │
│  GuardCenterActivity  PrivilegeGuideActivity                   │
│  + 4 个 Adapter  + ScoreRingView  + ReportExporter             │
└───────────────────────────┬──────────────────────────────────┘
                            │ 调用引擎 / 读取容器
┌───────────────────────────▼──────────────────────────────────┐
│  di 层（AppContainer：lazy 单例容器，持有 appContext）           │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│  core 层（业务核心，纯逻辑，可单测）                             │
│  ┌────────────┬────────────┬────────────┬──────────────────┐  │
│  │ rules      │ scanner    │ report     │ monitor          │  │
│  │ 评分知识库  │ 扫描/组件/  │ 报告模型    │ 新装事件          │  │
│  │            │ 签名分析    │            │                  │  │
│  └────────────┴────────────┴────────────┴──────────────────┘  │
│  ┌──────────────────────┬───────────────────────────────────┐  │
│  │ privilege            │ guard                             │  │
│  │ ShizukuBridge →      │ AutoResponder（统一响应管线） +     │  │
│  │ ShellExecutor →      │ 四条检测通道 + 周期巡检             │  │
│  │ UserService          │                                   │  │
│  └──────────────────────┴───────────────────────────────────┘  │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│  data 层（SharedPreferences + 手写 JSON）                       │
│  ScanHistoryStore · GuardConfigStore · InterceptLogStore       │
└───────────────────────────────────────────────────────────────┘
```

### 各层职责

| 层 | 包 | 职责 |
|---|---|---|
| UI | `ui.*` | 页面渲染、用户交互、权限提示、处置确认弹窗、守护中心 |
| DI | `di` | 提供引擎单例，避免全局静态散落 |
| 核心 | `core.*` | 全部业务逻辑：评分、解析、检测、处置、告警、守护 |
| 数据 | `data` | 体检历史 / 守护策略 / 拦截日志持久化 |

## 4. 模块地图

共 **9 个模块**（与 [02 · 核心模块详解](02-核心模块详解.md) 的编号一一对应）：

| # | 模块 | 关键类 | 入口 | 说明 |
|---|---|---|---|---|
| 1 | **规则知识库** | `PermissionRules`、`Finding`、`RiskLevel` | — | 单权限权重表 + 18 条组合规则；评分算法的唯一数据源 |
| 2 | **应用权限审计** | `PermissionAuditEngine` | `auditAll()` / `auditOne()` | `PackageManager` 枚举应用，权限 + 组件 + 来源综合评分 |
| 3 | **安装包静态扫描** | `ApkScanEngine`、`AxmlParser`、`ComponentAnalyzer`、`SignatureInspector` | `scanCommonDirs()` / `scanOne()` | 递归找 APK → 解析清单（权限 + 组件）→ 评分 → SHA-256 |
| 4 | **设备环境检测** | `EnvironmentCheckEngine` | `check()` | 7 类环境探测，输出发现项 |
| 5 | **体检编排** | `HealthCheckCoordinator` | `runFullCheck()` | 串行调度 2/4/3 并加权汇总为 `ScanReport` |
| 6 | **报告与历史** | `ScanReport`、`ScanHistoryStore` | `toMarkdown()` / `toJson()` / `save()` | 报告序列化与本地持久化 |
| 7 | **新装监听** | `InstallMonitorReceiver`、`InstallMonitor` | 广播 `PACKAGE_ADDED` | 装后体检 + 汇入守护管线 |
| 8 | **权限处置（可选）** | `ShizukuBridge`、`ShellExecutor`、`UserService`、`DisposalEngine` | `dispose()` / `terminate()` | 借 Shizuku 的 shell 权限执行 `am` / `pm` 命令 |
| 9 | **安全守护** | `AutoResponder`、`GuardService`、`GuardAccessibilityService`、`GuardSweep`、`WatchdogWorker` | `handle()` / `GuardSweep.run()` | 四条检测通道 + 事件驱动的秒级响应（默认只告警不处置） |

## 5. 核心数据流

### 5.1 一键安全体检

```
用户点「开始安全体检」(MainActivity.startCheck)
        │
        ▼
HealthCheckCoordinator.runFullCheck(includeApk = true)   [Dispatchers.IO]
        │
        ├─ 步骤1  权限审计： PermissionAuditEngine.auditAll()
        │            └─ PermissionRules.scoreOf() → Finding 列表 → ModuleResult
        ├─ 步骤2  环境检测： EnvironmentCheckEngine.check()
        │            └─ 7 项探测 → Finding 列表 → ModuleResult
        └─ 步骤3  APK 扫描（可选）： ApkScanEngine.scanCommonDirs()
                     └─ AxmlParser.parseFromApk() → scoreOf() → Finding → ModuleResult
        │
        ▼
computeOverallScore(modules)   加权：权限 50% / 环境 30% / APK 20%
        │
        ▼
ScanReport ──► MainActivity.renderReport()  →  ScoreRingView 动画展示
        └────► ScanHistoryStore.save()       →  写入 SharedPreferences
        └────► ReportExporter.exportAndShare() → Markdown/JSON + FileProvider 分享
```

### 5.2 安装 / 更新事件（守护通道 1）

```
系统广播 PACKAGE_ADDED / PACKAGE_REPLACED
        │
        ▼
InstallMonitorReceiver.onReceive()  →  goAsync() + 后台线程
        │  非替换 PACKAGE_ADDED → GuardChannel.INSTALL
        │  替换安装 / PACKAGE_REPLACED → GuardChannel.UPDATE（跳过自身包名）
        ▼
快速短路：InstallMonitor.audit() → score >= 阈值?
        │  否 → 到此为止（不写日志、不打扰）
        ▼  是
AutoResponder.handle(context, pkg, channel)   ← 汇入守护统一管线
```

### 5.3 守护响应管线（四条通道共用）

```
安装/更新 · 开机自检 · 前台唤醒(1s 轮询) · 无障碍事件 · 周期巡检(15min)
        │  （全部调用 AutoResponder.handle / GuardSweep.run）
        ▼
audit（10 分钟缓存）→ 读 GuardPolicy → decide()
        │
        ├─ IGNORE             → 无动作（不写日志）
        ├─ ALERT_ONLY         → 落日志 + 通知（默认行为）
        └─ TERMINATE_*        → DisposalEngine.terminate()
                                  ├─ am force-stop     （亚秒级终止全部进程）
                                  └─ pm disable-user   （按策略冻结，防自动重启）
             │
             ▼
        GuardEvent（含耗时与命令返回）→ InterceptLogStore.append + GuardNotifier.show
             │  （通知可带「立即终止」按钮 → GuardActionReceiver → manualRespond）
             ▼
        GuardSweep 巡检时复查"冻结的应用是否复活"（状态漂移检测）
```

### 5.4 应用处置（需 Shizuku 授权）

```
PrivilegeGuideActivity 引导用户完成「无线调试配对」
        │
        ▼
ShizukuBridge.requestPermission()  →  用户授权后 state = GRANTED
        │
        ▼
AuditActivity 点「处置」  →  DisposalEngine.isAvailable() 检查
        │  （不可用则引导去授权页）
        ▼
选择动作：DISABLE / ENABLE / UNINSTALL / CLEAR_DATA（破坏性动作标红二次确认）
        │
        ▼
ShellExecutor.exec(...)  ──经 Shizuku──►  UserService (shell uid 2000) 执行 pm 命令
        │
        ▼
ShellResult（永不抛异常）  →  Toast 反馈 + 刷新列表验证真实生效
```

## 6. 关键设计决策

| 决策 | 取舍与理由 |
|---|---|
| **不申请 `INTERNET` 权限** | 从权限模型上杜绝数据外传通道，可用 `aapt2 dump permissions` 验证 |
| **自研 AXML 解析器** | 为满足「业务逻辑零第三方依赖」，按 AOSP chunk 格式手写解析 |
| **组合规则评分**（而非单权限求和） | 单权限判别力弱，组合才有判别力；取「最高单分 + 组合加成 × 0.6」避免误判正常应用 |
| **自研 DI 容器** | 不引入 Hilt / Koin；所有引擎无状态或仅持有 Context，`lazy` 延迟创建即可 |
| **SharedPreferences 存历史** | 结构简单、上限 50 条，无需数据库 |
| **手写 JSON 序列化** | 使用平台自带 `org.json`，避免 Gson / Moshi |
| **处置走 Shizuku UserService** | Shizuku 的 `newProcess` 是私有 API，官方推荐用 UserService 承载动作 |
| **命令以数组传入** | `ProcessBuilder(cmd)` 不做字符串拼接，避免命令注入 |
| **自动处置默认关闭** | 默认只提醒、不处置；未授权 Shizuku 时界面直接拦下开关，不让用户误以为"开了就安全" |
| **守护模式与自动处置拆成两个开关** | 「要不要持续盯」与「盯到后动不动手」是两件事，默认组合是"盯着但不动手" |
| **无障碍通道只观察不操作** | `canRetrieveWindowContent=false`、无手势能力、无 `dispatchGesture`；处置一律走 `am` / `pm` 命令 |
| **事件驱动，而非行为监控** | 沙箱决定看不到其他应用行为；把能观测到的事件做到秒级响应，并如实标注边界 |

## 7. 权限模型

应用声明以下权限（最小化原则）：

| 权限 | 用途 | 必要性 |
|---|---|---|
| `QUERY_ALL_PACKAGES` | Android 11+ 枚举已安装应用 | 权限审计功能的前提 |
| `READ_EXTERNAL_STORAGE`（`maxSdkVersion=32`） | 读取存储中的 APK 文件 | 安装包扫描功能 |
| `POST_NOTIFICATIONS`（Android 13+） | 新装高危 / 守护告警时发本地提醒 | 守护告警 |
| `RECEIVE_BOOT_COMPLETED` | 开机后重排巡检任务并跑一次开机自检 | 守护通道 2 |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` | 守护模式的常驻通知（Android 14 起必须声明类型） | 守护模式（默认关闭） |
| `PACKAGE_USAGE_STATS` | 前台唤醒监听（需用户在系统设置中**手动授予**的特殊权限） | 守护通道 3（默认关闭） |

处置功能**不通过声明系统权限实现**，而是经用户显式授权后借用 Shizuku 的 shell 权限，
可随时在 Shizuku 应用中撤销。授权后获得的是 **shell（ADB，uid 2000）级权限**，不是 root：
可以 `am force-stop` 真实终止进程、`pm disable-user` 冻结，
但**读不到其他应用内存，也看不到其行为**——"实时行为监控"在非 Root 设备上不存在。
