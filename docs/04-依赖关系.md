### 值得注意的解耦点

- **`rules` 无外部依赖**：纯数据 + 纯函数，可独立单元测试。
- **`AxmlParser` 无 Android 依赖**：仅用 `java.io` / `java.nio` / `java.util.zip`，
  因此可在 JVM 单元测试中直接验证（`AxmlParserTest`）。
- **`core` 不依赖 `ui`**：业务逻辑可脱离界面复用（如被广播接收器、后台调用）。
- **`AppContainer` 被 `HealthCheckCoordinator` 直接使用**：编排器通过容器取引擎，
  这也是它不属于纯函数的原因。

## 3. 关于 Shizuku 的重要声明

IceGuard **只通过 Maven 依赖引入 Shizuku 官方的 `api` 与 `provider` 两个制品**，
**不内嵌、不重打包 Shizuku 应用本体**（`moe.shizuku.privileged.api`）。
Shizuku 应用本体需用户自行安装，并通过「开发者选项 → 无线调试」完成一次配对授权。

`app/src/main/aidl/com/ice/guard/IUserService.aidl` 与
`app/src/main/java/com/ice/guard/core/privilege/UserService.kt` 是本项目**自行编写**的
UserService 实现（用于配合 Shizuku 运行 shell 命令），并非 Shizuku 的代码，
版权归本项目所有，以 MIT 许可证发布。

### 声明式依赖（AndroidManifest）

```xml
<provider
    android:name="rikka.shizuku.ShizukuProvider"
    android:authorities="${applicationId}.shizuku"
    android:permission="android.permission.INTERACT_ACROSS_USERS_FULL" ... />
```

CHANGELOG 还提到新增对 Shizuku 的 `moe.shizuku.manager.permission.API_V23` 依赖声明。

## 5. 混淆（ProGuard / R8）保留规则

> 对应文件：[proguard-rules.pro](../app/proguard-rules.pro)

关键保留（release 构建开启 `isMinifyEnabled` + `isShrinkResources`）：

| 规则 | 原因 |
|---|---|
| `-keep class com.ice.guard.core.scanner.AxmlParser { *; }` | 保持可读性便于用户审计 |
| `-keep class com.ice.guard.core.rules.** { *; }` | 规则库保留 |
| `-keep class com.ice.guard.core.report.** { *; }` | JSON 手写序列化，字段名需保持 |
| `-keep class com.ice.guard.data.ScanHistoryStore { *; }` | 同上 |
| `-keep class com.ice.guard.core.guard.GuardChannel / GuardVerdict / GuardEvent / GuardPolicy { *; }` | **枚举常量名参与 JSON 持久化（`valueOf` 反查），被混淆则历史日志与策略静默读不出来** |
| `-keep class com.ice.guard.data.GuardConfigStore / InterceptLogStore { *; }` | 同上 |
| `-keep class com.ice.guard.core.guard.GuardService / GuardAccessibilityService / GuardActionReceiver / BootGuardReceiver { *; }` | **由系统按清单类名实例化；无障碍服务在独立进程中绑定，类名被改就永远连不上** |
| `-keep class com.ice.guard.core.guard.WatchdogWorker { *; }` | WorkManager 反射实例化 Worker |
| `-keep class com.ice.guard.core.privilege.UserService { *; }` | **该服务由 Shizuku 在独立进程中以反射方式实例化，类名/构造器被混淆或裁剪会导致处置功能静默失效** |
| `-keep class com.ice.guard.IUserService { *; }` + `$Stub` + `$Stub$Proxy` | AIDL 生成类保留 |
| `-keep class rikka.shizuku.** { *; }` / `moe.shizuku.** { *; }` | Shizuku 运行时反射 |

CI 中专门构建 `assembleRelease` 以验证这些规则没有裁掉靠反射实例化的类。
本仓库在 release 包上实测过：上述守护类全部以原名保留在 `classes.dex` 中。
